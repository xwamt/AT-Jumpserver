# AT JumpServer Terminal v0.2.2 发布说明

本版本基于 `v0.2.1`（CSRF 鉴权防御修复与快捷重连）基线，重点完成了 **JumpServer 5.0 协议与账号体系对齐**、**终端/SFTP 核心稳定性加固**、**界面交互与命令体验升级**、**大资产库/大文件性能提升** 以及 **工程模块化重构**。

## ✨ 更新亮点

### 1. JumpServer 5.0 协议与账号体系对齐
- **动态连接方式协商**：对接并缓存 `/api/v1/terminal/components/connect-methods/`（30 秒 TTL），自动匹配 `web_cli`、`db_client`、`web_sftp` 等连接方式；新增 **MariaDB** 协议识别支持；遇到本地客户端 / Applet / Virtual App 等不支持方式时给出明确错误提示。
- **KoKo 5.0 能力探测与无 Cookie 握手**：通过 `client/versions` 探测 KoKo 能力（404 自动回退兼容旧版本并按堡垒机隔离缓存），新增实验性配置项 `jumpserverManager.kokoBearerHandshake`，支持 5.0 WebSocket 握手直传 `Authorization: Bearer` 并在遇 401 时自动回退至 Ticket 认证。
- **多账号切换与别名账号模式**：完整支持托管账号与别名账号（`@USER`、交互式 `@INPUT` 弹窗录入凭证、`@ANON`、`@ALL`、`@SPEC`）；新增每资产偏好账号记忆，左键点击一键复用上次账号，右键点击 **「连接资产」** 可在多账号下随时弹窗重选账号。
- **终端到 SFTP 令牌复用与降级**：懒加载打开 SFTP 时自动复用终端持有的可复用连接令牌，握手失败时自动降级重新走 `web_sftp` 建连流程。

### 2. 核心稳定性与缺陷修复
- **首屏终端尺寸与重连保持**：修复会话建立前 `resize(rows, cols)` 丢失导致首屏退化为 `80x24` 的问题，并在点击重连后保留上一次视口行列数。
- **结构化连接状态与热更新**：终端状态栏接入结构化 `connecting` / `connected` / `disconnected` 状态同步，准确识别中英文断连文案（红/黄/绿灯与重连按钮不再误判）；右侧展示当前资产地址与协议标签，联动编辑器标签栏 `$(sync)` 重连按钮，并支持字号、字体、回滚行数、语义高亮、空闲断开时间修改后即时热更新已开终端。
- **SFTP 客户端心跳与断连自愈**：新增 20 秒发送 / 15 秒超时的 WebSocket `ping/pong` 心跳（`unref` 定时器）；会话断开后再次浏览或传输时自动销毁旧会话并无缝重建连接。
- **配置变更与资源清理联动**：新增、编辑、删除堡垒机或修改 `kokoBearerHandshake` 时同步失效 `JumpServerClientPool` 与 KoKo 能力探测缓存；修复 SFTP 编辑状态栏隐藏定时器竞态并将同步 `stat` 改为异步 IO；清理已完成的 MCP `terminalQueues` 内存条目并响应上下文移除事件；补齐堡垒机行内菜单图标，彻底解决悬停长文案遮挡域名的问题。

### 3. 界面、命令与工作流优化
- **命令面板净化与全局 QuickPick 直连**：将仅依赖树节点的右键命令从命令面板中隐藏，同时通过 `JumpServer: 连接终端` 支持 QuickPick 全局模糊搜索资产（按名称、IP、堡垒机、分组）快速直连。
- **资产树图标体系与精简右键菜单**：为堡垒机、空目录、分组、SSH、MySQL/MariaDB、Redis 与不支持资产提供清晰 `ThemeIcon` 图标区分；将资产右键连接菜单文案精简为 **「连接资产」**（`Connect Asset`），避免过长截断。
- **SFTP 文件树高频操作补全**：点击“待连接”占位行直接刷新并懒加载建立 SFTP 会话；单击文件直接打开只读预览；新增 **跳转到路径**、**新建文件** 及目录右键 **在终端中打开目录**（向当前 SSH 终端输入安全转义后的 `cd` 指令）。
- **堡垒机配置面板体验提升**：补全 URL/组织 ID/密码输入框占位与编辑留空提示；新增内联 **测试连接** 按钮（不落盘、不关闭面板即可校验账号并探测可访问组织）以及请求中的防连击禁用状态。

### 4. 性能与工程架构演进
- **大资产库节点索引缓存**：`JumpServerTreeProvider` 按刷新周期构建 `BastionTreeIndex` 索引结构，消除大资产库展开子分组时重复遍历过滤全量资产的开销。
- **SFTP 4 MiB 流式分块上传**：`JumpServerSftpSession.uploadFromFile` 使用 `open()` 配合固定 4 MiB 复用缓冲区逐片读取上传，大幅降低大文件上传时的堆内存峰值。
- **工程卫生与模块化拆分**：清理生产 `l10n` 包内残留的测试字符串并加固 `nls.test.ts` 反向校验与危险 payload 守卫；去除 `package.json` 构建脚本的重复拷贝；将 `JumpServerClient.ts`（拆分为 `cookieJar.ts`、`assetNormalizer.ts`、`tokenPayload.ts`、`kokoEndpoints.ts` 并保留重导出）与 `extension.ts`（拆分为 `src/commands/{bastionCommands,assetCommands,sftpCommands,mcpCommands}.ts`）渐进模块化，持续保证 `dist/extension.js`、`dist/mcpRuntime.js` 与 `dist/policy-runtime.js` 严格拆包隔离。
